Foundry on Paved Paths

Foundry rebuilt the agent harness it runs on. This document lists each custom mechanism, the paved path that already does the job, and the order to move over in.

2026-10-27 · base main@45c182c9 · scope extensions/foundry + src/main/agents/acp

Context and problem

Foundry turns a tracker issue into a draft pull request. The Forge shapes a work order with a scout, an architect and a red team; the Line runs agents in git worktrees, checks their work and opens the PR. It is about 50,000 lines of TypeScript with seven dependencies. Most of those lines rebuild what Claude Code, the Claude Agent SDK, git, GitHub and the app's own SDK already do. The rebuilt parts fail where the originals do not. Today one order sat on "drafting the plan" for over eight minutes although the architect had written the plan in 56 seconds, and the base-branch check opened about 40 macOS crash dialogs. Both failures trace to custom code in the path of a paved one.

Goals and non-goals

Goals

  • Every Foundry mechanism either uses a paved path or shows in this document why none fits.
  • The agent boundary (tools, permissions, settings, output) is set by Claude Code configuration, not decided call by call by Foundry code.
  • A plan draft for a small ask finishes in under three minutes, measured from converge.started to order.redrafted in the ledger.
  • No refusal ends a turn. An agent that is refused gets the reason in the same turn.
  • Net deletion: the Foundry source gets smaller with each phase.

Non-goals

  • Replacing Foundry with another product. The survey below found no embeddable tool that does the Forge, the gates and the supervision surface inside Terminator.
  • Changing Foundry rule 1 ("nothing is written into a target repository", extensions/foundry/CLAUDE.md). Several paved paths are rejected for breaking it, and that is stated where it happens.
  • Changing the order model (order/schema.ts). It is already Zod, the paved path.

Options considered

A. Rebuild the Line as Claude Code workflow scripts

Claude Code workflows give agent(), parallel(), pipeline(), per-agent schemas and deterministic resume (workflows).

  • For: deletes the scheduler, waves and resume code, and replay comes for free.
  • Against: no mid-run user input, so gates cannot sit inside a run. Agents do not run in Terminator's visible tabs, and the concurrency cap is 16.

B. Adopt an existing app and retire Foundry

Vibe Kanban (Apache-2.0), Nimbalyst (MIT, Electron), Conductor (proprietary) and the Copilot coding agent all run agents in worktrees and open PRs.

  • For: the most code deleted.
  • Against: they are apps, not libraries Terminator can embed. None has the Forge, risk-priced gates or a three-valued base check. The Copilot agent runs in GitHub's cloud.

C. Keep Foundry's domain, move every mechanism under it onto the paved path (chosen)

Foundry keeps the order model, the gates, the standing derivation and the supervision surface. Everything between Foundry and the agent becomes Claude Code configuration. Everything between Foundry and git or GitHub becomes the native command.

  • For: it fixes both of today's failures at their cause, ships phase by phase, and each phase is a net deletion.
  • Against: Foundry stays a large extension. The policy move changes what FR-029 and FR-050 enforce, so it needs one real run before the old code goes.

Decision

Option C. Its rule: isolate, then trust. Every tool in the survey runs the agent inside a boundary (a worktree plus the OS sandbox, a container, or a VM) and lets the harness's own permission engine decide each call. A person is asked only at irreversible edges: push, PR, merge and network. Foundry instead reads every shell command itself, on the host, and refuses by cancelling the turn. That is the source of most of the 45 runtime fixes and of today's lost plan. Option A stays open for the run graph once workflows accept mid-run input.

Phase 1: the agent boundary (fixes today's plan-draft hang)

  1. Pass the role's tools. In runtime/supervised-runner.ts claudeOptions, add tools from the role (read → Read, Grep, Glob; search → WebSearch, WebFetch). The architect also gets Write for its one output path until step 4 removes that need.
  2. Stop inheriting the operator. Add settingSources: ['project'] to claudeOptions.
  3. Generate permissions per role. Add runtime/role-settings.ts: a pure function from role and autonomy to a settings object with permissions.allow/ask/deny, sandbox.enabled and permissionMode (dontAsk for read-only roles and lights-out). Move deny-rules.ts into permissions.deny. Keep one PreToolUse command hook for the Artifact path rule, which no rule specifier expresses.
  4. Use structured output for proposals. Pass outputFormat: { type: 'json_schema', schema: z.toJSONSchema(ProposalSchema) } through _meta.claudeCode.options (the adapter reads it at acp-agent.js:358). Read the result from the final message. Delete outputContract, retryForRefusal and the proposal-file round trip in forge/intake-turn.ts.
  5. Collect on every turn end. Until step 4 lands, collectProposal also runs on a cancelled turn, so a written plan is not left waiting for the session to end.
  6. Delete shell-split.ts, read-only-policy.ts, autonomy-policy.ts, most of tool-decision.ts, the five-minute hold, tellWhyRefused, the question branch and the resend counters in src/main/agents/acp/agent-service.ts. An operator's typed answer goes out as a normal prompt after end_turn.

Phase 2: Forge state

  1. Store intake.state (drafting | reviewing | fixing | ready | failed) and a deadline on the order (order/schema.ts). readiness.ts reads it instead of replaying ledger action strings in intake-outcome.ts. A passed deadline or a run.stalled becomes failed with a named next move.
  2. Merge acceptance and plan.units by id in applyProposal.
  3. Delete the bugfix, refactor, speckit and direct recipes, their tests, and the SPECIFY_FEATURE env.

Phase 3: Line on git and GitHub

  1. git worktree add --lock in line/worktree.ts. Delete both git worktree prune calls. Cut lanes and the baseline from origin/<base> after one git fetch. Never -B or branch -D a branch Foundry did not create.
  2. Replace line/restack.ts with gh pr update-branch --rebase <url>. Record restackedFor on conflict, so the refinery stops re-raising a decided gate every 60 s.
  3. Change the wave barrier in execution-waves.ts to start a ready node when a slot frees.
  4. Pass explicit timeouts on gh pr checks, gh run view --log-failed and git fetch (line/ci.ts:66,153, restack.ts:20). The core default is 10 s (src/main/extensions/api.ts:597).
  5. Base-branch proof: read the base commit's CI conclusion first (nearest ancestor with a run when HEAD is [skip ci]). Run locally only what CI did not measure, and prefer the repository's aggregate script. Parse workflows with yaml.load, and skip ${{ }} steps.
  6. Map the Format check to a check script (format:check), never a writer. Today hints/node.yaml:13 maps it to the script format, which in this repository is prettier --write . (package.json:42). It always passes and rewrites lane files, although format:check exists at package.json:43.

Phase 4: state and UI

  1. Move orders, gates, graphs, ledger and signals into api.db tables keyed by (data_root, order_id). Each store writes in a transaction and then calls announce. Delete foundry-index.ts caching and the JSONL appenders.
  2. Delete the factory hall, timeline-store, the run.timeline and run.activity channels, and the terminator.foundry.view setting. Move the status tiles to the Ledger.
  3. Swap local primitives for extension-ui components. Move ConfirmButton into extension-ui.
  4. Use createIpcRegistrar, and export a typed FoundryApi channel map that removes the 56 casts.
  5. Transcript tailing is replaced by api.agents.onUpdate and onEnd. Add openAsks to the SDK's AgentsAPI, then delete pending-permissions.ts.

What stays custom, and why

  • Order model, compile checks, standing. Zod and a pure function; no library holds "whose move is it" across three stores.
  • Risk-priced gates. Existing tools offer fixed autonomy tiers (Factory --auto low|medium|high, droid exec). Pricing a gate per change is product logic.
  • Repository profile with a "not measured" result. No tool keeps three outcomes for a check, and rule 1 rules out per-repo config.
  • Lane worktrees under the data root, the ladder, CI rounds, PR text. Each paved option writes into the target repository or needs a pushed commit.
  • Cross-order file-overlap queue. A merge queue serialises at merge time only. Keep it small.

Testing and verification

  • Each bug in the list below gets a failing test first, in extensions/foundry/tests/, before its fix.
  • role-settings.ts gets table tests. Each role and autonomy pair maps to the expected settings, including the bypass cases found in this audit: git -C . push, sed -i … src/ from a docs-only role, and git -c core.fsmonitor=… status.
  • One live run per phase, using the "Drive Foundry live" setup (temporary repository plus a seeded .foundry/orders). Phase 1 passes when a small order's plan draft takes under 3 minutes, measured with python3 converge_timing.py on its ledger.
  • Every phase: npm run ci:local exits 0 before push. Report the line delta with find extensions/foundry/src -name '*.ts*' ! -name '*.test.*' -exec cat {} + | wc -l.

Risks and mitigations

  • The policy move changes what is enforced (FR-029, FR-050). Mitigation: write the bypass cases above as tests against the generated settings, run one live order, and only then delete the old policy.
  • Structured output through ACP is unproven. The adapter accepts outputFormat but does not forward structured_output to the client. Mitigation: a spike that reads it from the final transcript result, and step 5 of phase 1 as the fallback.
  • The sandbox can block legitimate network use (installs, gh). Mitigation: a per-role host allowlist in the generated settings.
  • Deleting the hall removes run replay. Mitigation: the ledger keeps every event. Replay can return as a list view if someone asks for it.
  • Moving records to api.db changes the e2e harness, which writes records by hand (restartFoundry). Mitigation: seed through the stores.

Open questions

  • Does a PermissionRequest hook behave the same under the ACP adapter as under the SDK? ADR 130 confirmed only PreToolUse.
  • What message does Claude get from a dontAsk refusal, and is it enough without a hook?
  • Does additionalDirectories load mounted skills? The docs say only --add-dir does (supervised-runner.ts:414). If not, the ci-fix skill never loads; the SDK plugins option is the replacement.
  • Should budgets.tokens be enforced through the SDK's maxBudgetUsd / --max-budget-usd (headless) per agent? The schema keeps it nullable on purpose (order/schema.ts:185-187).
  • Is TanStack Query approved as a new dependency (Constitution IV)?
  • Is merge queue available on this repository's plan? That decides how much of the refinery can go.
  • Why was the installed app still v0.1.169 when v0.1.170 had been released for more than nine hours?

Alternatives rejected

  • Spec Kit as the Forge: writes specs/ into the target repository and produces markdown, not a typed order.
  • Claude Code --worktree for lanes: creates <repo>/.claude/worktrees and one worktree per session.
  • claude-code-action and /autofix-pr for CI rounds: need a workflow file or the GitHub App on the target repository.
  • Temporal, Inngest, Restate: each needs a server process; copy their journal-and-replay pattern instead.
  • Agent teams: experimental, no worktrees, not available through the SDK.
  • electron-trpc: needs a hook in the core preload, which extensions cannot touch.
  • A shell parser library in place of shell-split.ts: Claude Code already parses the command; a second parser repeats the job.
