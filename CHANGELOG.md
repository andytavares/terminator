# Changelog

All notable changes to Terminator are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Added

- **A Foundry research order ends in a Claude artifact** (ADR 119). The author publishes its document as a Claude artifact during an unattended run, with no prompt and no browser tab. Foundry checks the link against the author's own session. The verifier reads the document it passes. The finished order is `shipped`. The ticket moves to In Review, with the link as a comment. The link opens from the order list, the open order (**Open artifact**, **Open local copy**, **Copy link**), the gate cards, the factory hall and the factory site. Home's thread drawer shows **Open artifact** through a new `links` field on thread facets (`@terminator/extension-sdk` 5.1.0)
- **Home is the Desk** (ADR 117). The app opens on a screen that shows what waits on you, what is in flight and today.
  - A full-width **Your move** band gathers asks from core and from extensions (Git Integration, Foundry, Task Vault, through `api.home.publish`). You answer an agent's numbered question in place with `1`-`9`.
  - **In flight** lists work threads by whose move it is. It opens a drawer with a written summary, agents, token use, the pull request and a timeline.
  - A **Today** rail, **Plan today** on the first view of a day, **Search** (`Cmd+K`) and **Start work** (`Cmd+N`) complete the screen.
  - **Insights** is a second view of cards. Each card is titled by the question it answers.
  - Claude Code's `Notification` and `Stop` hooks tell Terminator when an agent asks. Terminator adds them to `~/.claude/settings.json` beside the `SessionStart` entry.
  - While Home shows, the branch tree is hidden. `Cmd+B` shows it. **Hide the branch tree on Home** in Settings turns this off.
  - The Ledger and the Logbook are gone. `contributes.homeSection` is now `contributes.insightsSection`.
  - Agent waiting time is kept 90 days in `attention-log.json`
- **Foundry proves the base branch while an order is shaped** (ADR 111). A new order runs format, lint, tests and build on its base branch in visible terminal tabs while the architect works. It mends a broken install once and records the result. The Hand off step gains a seventh row, "The base branch builds and passes its checks", with **Check again** and **Skip this check**. The backend refuses to agree an order that it holds. The final check reuses a pass recorded on the same base commit instead of running it again. Every draft pull request gains **What's left for you**: the criteria that did not pass, checks not measured or failing on base, accepted findings, assumptions nobody struck and open questions
- Icon tooltips everywhere: `installIconTooltips` in the design system names every icon-only control when the pointer rests on it or keyboard focus reaches it, from the `title` or `aria-label` that the control already has. The core renderer and every extension view install it. It draws in the page, because the native tooltip did not appear in an extension's view
- `ModalShell` in the design system: the modal behaviour around any content, built on the native `<dialog>` element (ADR 110). Every modal surface is now that one shell: `Dialog` (its props are unchanged), Settings, Quick Actions, Notepad's search and quick create, and Task Vault's block, recurrence and query-confirmation dialogs. In all of them Tab stays inside. The screen behind cannot be clicked or tabbed to. Focus returns to what opened the modal. A toast shown while a modal is open appears over it and can be pressed. Every modal is centred in its window on both axes. Quick Actions and Notepad search no longer sit near the top. Removed with the hand-written versions: `focus-trap.ts` (`captureFocus`, `focusableWithin`, `trapTab`), `nestedLayerValue`, `useContainingLayer` and `useDismissible`'s `captureEscape`. Settings' backdrop loses its blur. The application log and the notification drawer are announced as regions, not dialogs
- `SegmentedControl` in the design system: one choice out of a few, drawn as joined buttons. It uses the keyboard of the WAI-ARIA radio group: arrow keys move focus and the choice, Home and End work, disabled options are skipped, and only the chosen option is in the Tab order. Stories in both themes and a behaviour spec
- Extension views draw in the bundled IBM Plex fonts: The core renderer and the entry of every extension view import `@terminator/extension-ui/fonts`. Before, these views had fallen back to system fonts. `npm run test:visual` screenshots every Storybook story with Playwright in both themes. Linux baselines live in `packages/extension-ui/visual/__screenshots__/linux` (ADR 098). `Dialog` actions take `submit: true`, so a form dialog submits on Enter
- The design system foundation (ADR 098). `packages/extension-ui/src/tokens.css` is the one definition of colour, space, type, radius and layer tokens for both themes. The core renderer imports it, and its `--bg-*` names became aliases. The extension host injects it. Remote Control serves it instead of its 269-line copy. New components `Button`, `Tabs`, `Markdown` (moved from Git Integration's `RichContent`), `RelativeTime` / `formatRelativeTime` and `usePolling` (moved from Foundry). IBM Plex Mono ships with the app instead of loading from fonts.googleapis.com. Storybook 10 documents every component in both themes, and `npm run test:stories` runs the stories as tests
- **Quick Actions** replaces the command palette with a leader + which-key panel.
  - `⌘P` still opens it from anywhere: a terminal, Home, Overview or any extension view. It reaches an extension's own `WebContentsView` through a `before-input-event` hook that the extension host never had.
  - A letter acts immediately (`g` then `p` pushes the focused branch).
  - `/`, or `⌘P` again, switches to fuzzy search over label, category and description.
  - Pins (`⌘.`) and frecency-ranked recent actions sit first and survive a restart.
  - An action that cannot run shows dimmed with its reason. It does not disappear.
  - The panel covers every direct shortcut in `useKeyboardShortcuts.ts` and the menu accelerators in `main/index.ts`. A unit test fails on any accelerator with no matching action.
  - v1 covers Git, Notepad, Task Vault and Foundry through a manifest `contributes.quickActions.group` and `contributes.commands[].mnemonic`.
  - Custom shell and Claude-prompt actions ship in v1 (Settings → Quick actions, global or per-workspace). They use the variables `{cwd} {branch} {worktree} {repo} {issue} {selection}`.
  - A custom action is refused when an agent is mid-turn or when a shell body is over the 1024-byte PTY line limit. A body never runs with a variable silently left empty.
  - `api.keyboard.register`, which nothing ever dispatched, is deleted.
  - See ADR-057, which supersedes ADR-027's stale claim that `⌘K` opens the palette
- **Foundry**: the SpecKit Pilot, rebuilt as a software factory. Foundry converges an idea or a tracker issue into a **work order** that compiles, and hands it to an orchestration that does the work. The ten-phase pipeline is gone. Nine decisions on a one-line change became zero to two, because nothing stops unless a **named rule** fires. Every interruption says which rule raised it, what it looked at and what happens if you ignore it. Work ends in a draft pull request without a request, and the decision offered is whether to mark it ready. See ADR-040, ADR-041, ADR-042 and `specs/037-foundry-software-factory/`
  - **The Forge** reads the repository before it asks anything. It refuses to hand off until six mechanical checks pass: no open questions, every criterion falsifiable, coverage complete in both directions, risk graded against _this_ plan, adversarial findings resolved, and budgets set
  - **The Line** picks a _recipe_ and runs it. A recipe is a YAML file, not a hardcoded pipeline; the ten SpecKit phases are one of six recipes that ship. The Line runs typed roles and a verifier that is structurally forbidden to resume the builder's session. Its verification ladder stops at the first failure, and its verdicts have three values, where **"not measured" is never a pass**
  - **Nothing is written into the repositories it works on.** No scaffolding, no configuration, not even a `.gitignore` entry. Records go to `terminator.foundry.dataDir` or `<workdir>/.foundry/`. A repository _can_ carry its own `.foundry/recipes/…`, and those win, but no repository needs one
  - **No hardcoded toolchain.** A probe reads manifests, tool configuration, Makefiles and CI, and never executes them. It records the real command or `null`, and `null` means the check reports "not measured"
  - **An autonomy dial** selects which rules are live. Five stay live at every setting. So lights-out opens a draft pull request without you, still does not merge, and still tells you when a run has stopped moving
  - **One order across several repositories.** Foundry derives the shared files from the plan instead of a declaration, and holds consumers until their producer merges
  - **A ledger** of every decision: who or which rule made it, and why. Only when you ask, a curator says what you keep rejecting and offers a rule that cites the specific entries
  - **Write-backs are per order** as well as per configuration. A run against another person's repository is a reason to turn one off without changing the setting for every later order
  - **Intake is an agent turn** (ADR-043). The architect runs over the seeded draft, read-only and in the repository itself, and _proposes_. It can never write the order's status, id, source, provenance, context or findings. A proposal that reaches for one of them is refused, not quietly trimmed
- `ExtensionAPI.issues.states`, `.transition(intent)` and `.supportsTransitions()` (v2.3.0). An extension can move an issue along its own workflow, and can change nothing else about it. The API takes an intent, because Linear sets a target state and Jira can only perform a transition available from the current status. Linear supports it; Jira reports it as unsupported. ADR-041
- `packages/extension-ui`: the single implementation of the shared extension UI behaviour. It is published to the bundled extensions, to third parties and to the core, which now wraps its `ConfirmDialog`. It is source-only, with `react`/`react-dom`/`lucide-react` as peer dependencies, so it adds no build step and no second React. It ships `Dialog`, `ConfirmDialog`, `Popover`, `ToastRegion`, `EmptyState`, `IconButton`, `useDismissible`, the focus trap, the per-document modal-depth registry and the layer scale. ADR-038, ADR-039
- A light theme for extension views. `EXTENSION_BASE_CSS` had one dark `:root` block and no `[data-theme='light']` block. Nothing in main, the preload or any extension mentioned the theme. So when the app switched to light, the core went light and every extension panel stayed dark. The palette mirrors the core's AA-verified values. `ExtensionViewHost.setTheme` stamps `data-theme` on each extension document, restamps every open view on a change, and remembers the theme for views created later
- `extension.setTheme` on the API manifest (`extension:set-theme`), native-only
- `api.ui` on the Extension API (v1.3.0). `api.ui.toast(message, { tone, duration })` shows a message in the extension's own view, and `api.ui.layers` publishes the four-step stacking scale
- `docs/EXTENSION-STYLE.md`: the written house rules for extension UI. `no-restricted-syntax` selectors on `extensions/*/src/**/*.tsx` enforce its vocabulary rules, and a 19-case fixture spec at `tests/unit/lint/extension-vocabulary.spec.ts` tests them
- `tests/e2e/extension-themes.spec.ts` walks every visible text node in each extension view, in both themes. It resolves the composited backdrop through the translucent layers above the node and asserts WCAG AA. Reading the stylesheet cannot answer this, because `color-mix` and layered alpha resolve only in a browser
- Remote Control now shows what it is doing: on, starting, on but local only, or failed. It also shows the address, a QR code that carries the password, and a live list of connected devices with a disconnect control for each
- `--tm-accent-text`, `--tm-accent-hover`, `--tm-on-success`, `--tm-on-warning`, `--tm-on-danger`, `--tm-overlay-*` and `--tm-scrim` tokens, all defined in both themes
- A three-step icon scale: `tm-icon-sm` (12px), `tm-icon` (14px) and `tm-icon-lg` (16px), injected with the colour tokens. It replaces 170 `size={n}` props that spread seven ad-hoc values across a 6px band. The `size` prop is now an ESLint error in extension source. `<select size>` and `QRCodeSVG` are named exemptions
- `captureEscape` on `useDismissible`, for a surface that hosts an editor which stops keydown propagation before the document gets the event
- A named `action` on the shared `Toast`
- `tests/e2e/merge-flow.spec.ts` builds a repository in the middle of a merge and drives MergeFlow. MergeFlow was the one surface the audit could not check, because it needs populated git state. The spec also holds Git Integration's contrast checks, which the other harness cannot reach: git-integration has no global tab, and its merge surfaces exist only while a merge is in progress
- `tests/e2e/extension-keyboard.spec.ts` (SC-003) and `behaviour-matrix.spec.tsx` (SC-002). Before, these two criteria were satisfied by inference from the shared components, not by measurement

- Light mode CSS token overrides (`[data-theme="light"]` block in `styles.css`)
- `db:health` IPC channel that returns `{ ok, message? }`, wired into the About dialog
- Spacing token scale (`--space-1` through `--space-12`) in CSS `:root`
- The IPC remote-access allowlist is centralised in `src/main/remote/remote-accessible-channels.ts`. This one auditable set is the entire remote attack surface. The bridge denies by default across `invoke`, `send` and `subscribe`. `remote-accessible-channels.spec.ts` asserts that the set stays in sync with the channels the `/app/` shim uses, so enforcement and the allowlist cannot ship half-done independently
- Per-IP failed-auth rate limiting on the remote-control server (`auth-rate-limiter.ts`): 10 failures / 15 min → `429` lockout
- An end-to-end Playwright test (`tests/e2e/remote-app.spec.ts`). It starts the app in an isolated profile, turns on remote control, loads `/app/` in a real browser, and asserts that the IPC bridge serves a workspace. CI runs it as a new `e2e` job (macos-14). It guards against the `/app/` regression class
- `npm audit --audit-level=high` step in CI lint job
- `XTERM_THEMES` constant with dark and light palettes, and a MutationObserver in `TerminalInstance` that re-themes live terminals
- `(extension_id, key)` composite primary key on the `settings` tables in the notepad and task-vault extensions, with a backfill migration
- `diagram_tags` relational join table, which replaces the `diagrams.tags` JSON column. The migration backfills existing tags and drops the column
- `assertTableAllowed` guard in `migrate.ts` prevents SQL injection through table names. Column and table names are now quoted
- Per-row `logger.warn` and a summary `logger.info` in the `migrate.ts` legacy migration
- `scheduleWeeklyReviewNudge` interval guard in task-vault, which prevents double scheduling
- `_spCount = 0` reset in `closeAppDb()`, so the savepoint counter restarts after a re-init
- ADR-020: MCP stdio sidecar removal

### Changed

- **The PR overview is four sections** (ADR 112, Amended). The header and the status strip stay pinned. The tabs are **Change** and **Discussion · N**. The properties rail sits beside both tabs and scrolls on its own; below 900px it is a third **Properties** tab. The description is always clamped. Comments are clamped at 160px, and only the last three show; the rest are behind **Show N earlier comments**. Strip, rail and Brief icons are flat
- The Code Reviews PR overview has an **At a glance** aside (checks, reviewers, author, branch, opened, merge state, linked issues) beside **Description**, **Discussion · N** and **Insights** tabs. Before, it was one long column. **Summarize** on the Description and Discussion tabs runs the review agent's read-only `claude` through the new `review-agent:summarize` channel (ADR 111). The summary shows in place and is not stored. A failure shows its reason with **Retry**. The channel is local only, not in `REMOTE_READ_CHANNELS`.
- Notepad's Edit title & tags is the design system's `Dialog`. Tab stays inside it, and Enter in the title saves (before, only ⌘↵ saved). Its heading is "Edit note" or "Edit diagram". Quick create's Note, Diagram and Folder choice is a `SegmentedControl` that the arrow keys move through. The Archived and resolved-comments disclosures draw a chevron icon instead of `▼`/`▶` and say whether they are open (`aria-expanded`). The resolved toggle drops its "(show)"/"(hide)" suffix. Task Vault's History sections (completed tasks, archived projects, archived areas) and Data tools' Export & import and Database are `Tabs`, with the count in a separate span and the labels in sentence case. History's 7, 30 and 90 day window is a `SegmentedControl` that reads "7 days", not "7d". `<button>` count: `extensions/notepad/src` 32 → 29, `extensions/task-vault/src` 37 → 31
- Git Integration's buttons are the design system's `Button` and `IconButton` (ADR 098). Its Write and Preview switches (pull request description, comment composers) are `Tabs`. Its two- and three-way toggles are `SegmentedControl` radio groups: diff layout, Files or Chapters, since my review or whole PR, the View menu's three groups, the agent's request and model, and Keep both's order.
  - The `git-view__btn`, `rd-btn`, `rf-btn`, `rc-btn`, `ap-btn`, `rh-btn`, `vm-btn`, `action-bar__btn` and 30 other per-control button rules are deleted.
  - `<button>` in `extensions/git-integration/src` went from 149 to 32. Of those, 16 are in `ReviewDiffPane` and its rows (out of scope). The rest are status pills that open a popover, menu items, the formatting switch, list rows and section disclosures.
  - What looks different: agent actions lose their violet tint and take the ordinary weights. Pop out shows an icon instead of `⬡`. The overview's close is an `X` icon instead of `×`. Undo last shows an icon instead of `↩`. Commit & Push no longer prints `⟳` while it pushes. Keep mine and Keep theirs mark their side with a coloured dot instead of `▼`, and fill when chosen.
  - The merge resolver's Escape shortcut is removed. It ran only when Keep both was already closed, so it did nothing
- Foundry's buttons are the design system's `Button` and `IconButton`, and its hand-built segmented controls are `Tabs` and `SegmentedControl` (ADR 098).
  - The `sk-btn` and `fdry-btn` families are deleted, with the rules that restyled every `button` inside 14 action rows, forms and toggles.
  - `<button>` in `extensions/foundry/src/components` and `src/renderer` went from 88 to 22. The rest are list rows, choice cards, the surface switcher, and the factory hall's controls, which use the hall's fixed palette, not the theme.
  - What looks different: Record and Factory in the Ledger are tabs. The time window, and Idea or Ticket in the order form, are radio groups that the arrow keys move through. The order form's back control has an arrow. Stop and End this agent are drawn as destructive. A mute's remove mark is an icon, not `✕`
- Task Vault's buttons are the design system's `Button` and `IconButton`.
  - Deleted: the `tv-btn` family (16 classes), its `--tv-btn-h-*` heights, the per-control button rules, and the rules that restyled every `button` inside 14 pickers, forms and action rows.
  - `<button>` in `extensions/task-vault/src` went from 197 to 37. The rest are list and calendar rows, status checkboxes, segmented controls and tabs, chips, listbox options, section disclosures and the date field's trigger.
  - What looks different: buttons have the design system's heights (about 29px, 22px small), where Task Vault drew 26px and 22px. Outline buttons are secondary. A task row's hover actions are plain icon buttons over the row's fade, not bordered squares.
  - The red, amber and green hover tints on archive, delete, block and unblock are gone. The recurrence control is no longer accent-coloured once set; its name still states the rule.
  - Mark blocked is primary, not amber. The recurrence dialog's Remove and the stale-task Delete are danger buttons, not red text. The inline project-task Save is a "Save" button, not a check icon.
  - Restore uses `RotateCcw` instead of "↩", Hide tasks uses a chevron instead of "▲", and Previous day uses `ChevronLeft` instead of a rotated right chevron.
  - 23 icon-only buttons with no accessible name (the close, cancel, refresh and month controls) now have one. The calendar toggle is a pressed button named Calendar.
  - An area card's archive and delete controls show at full strength on hover and on keyboard focus
- Notepad's buttons are the design system's `Button` and `IconButton`. Its `notepad-btn-ghost`, `-primary`, `-icon`, `-outline`, `-export`, `-new` and fifteen per-control button rules are deleted. `<button>` in `extensions/notepad/src` went from 67 to 32; the rest are list rows, menu items, chips, switches, segmented controls and the editor's gutter marker. What looks different:
  - The empty state's buttons drop from 14px to 13px.
  - The comment card's Save, Cancel and Send are primary and ghost, not outlined. Reply and Resolve are ghost buttons, not bare links. Resolve is no longer green once resolved.
  - The comment's delete control no longer turns red on hover, and it now also shows on keyboard focus.
  - The diagram's Comment control turns primary while you place a comment, and reports `aria-pressed`. The diagram thread's Resolve and Delete get accessible names; before, they had only a tooltip.
  - New uses a plus icon instead of "+". The quick-create "cancel" reads "Cancel".
  - The tag filter is no longer accent-coloured while tags are active; its label still counts them.
  - Keyboard hints inside buttons use the design system's `tmui-kbd`
- `IconButton` takes the attributes of a button (`disabled`, `aria-expanded`, `style`, a handler that receives the click). It takes a `size` of `sm` (20px, 12px icon) for dense rows. It no longer highlights on hover while disabled. The primary `Button` keeps its accent on hover. Before, the base hover's card background won, which in the light theme put the light label on light grey
- `Tabs` also comes in parts (ADR 098): `TabsRoot`, `TabList`, `Tab` and `TabPanel`, shaped like Radix Tabs. A tab list can share a toolbar row, and its panels render where the caller puts them. A tab takes any content, with `accessibleName` for a label that holds a count. A `TabList` can be `vertical` (Up and Down). A tab's `aria-controls` now names only a panel that is in the document. The Reviews dashboard's sections, the PR review inspector's Agent and File tabs, and the chapter list use it. They gain arrow keys, Home and End, and one Tab stop; the dashboard and the inspector had none. Each tab is named with its count ("Needs you, 3"). They take the design system's tab look: 13px labels, 6px by 12px padding, and a 4px gap before a count
- Remote Control's buttons are the design system's `Button`, and its `rc-btn` and `settings-section__btn` rules are deleted. The settings buttons lose their card background and get a 12px label, and the status band's actions are a point larger. Some menus now close through `useDismissible` instead of their own document listeners: Notepad's tag filter and note and folder context menus, and Task Vault's context filter, area picker and smart-input suggestions. So the dropdowns and menus that lacked it now also close on Escape, and count as open surfaces for the extension-exit gesture
- One Markdown renderer (ADR 098). The design system's `Markdown` gains `inline` (one line inside a button or a label) and `fetchesNothing` (raw HTML dropped unparsed, no image or `src`, for text anyone can write). It opens mailto links through `onOpenLink`. An empty or `javascript:` link no longer reloads an extension view. The core's issue drawer, Foundry and Task Vault render through it. It replaces core `IssueMarkdown`, Foundry's hand-written `Markdown`/`MarkdownInline` and Task Vault's `renderMarkdown`, which wrote HTML strings into `dangerouslySetInnerHTML`. Visible differences:
  - Foundry and Task Vault now render tables, block quotes and strikethrough.
  - Task Vault's checklists show checkboxes instead of ✓/○ glyphs.
  - A link to anything but http(s) or mailto shows as an inert link, not as its source text.
  - Raw HTML in a Task Vault description is dropped, not shown as text
- Extension SDK 3.0.0 (ADR 096): every extension channel is a `ChannelSpec`. The core parses its payload with its schema before the handler runs. The unvalidated `registerHandler(channel, handler)` form is removed, and a registration without a schema throws at activation. Foundry, git-integration, notepad, task-vault and remote-control declare a schema on every channel. See `packages/extension-sdk/CHANGELOG.md`
- Extension SDK 2.0.0 (ADR 094): `@terminator/extension-sdk` is the one declaration of the Extension API. The core implements it and the compiler checks it. Extensions import it and `@terminator/extension-ui` instead of core source, and `npm run lint` rejects any import that leaves an extension's directory. The SDK gains runtime entries with `defineChannel`, `invoke`, `mountExtension` and `writeJsonAtomic`, which replace the copies that the core and the extensions kept. See `packages/extension-sdk/CHANGELOG.md`
- The core's eight hand-built dialogs (About, Name this terminal, Link a work item, Link an issue, Create and Edit workspace, Create branch, Move to branch), its toast and its empty state render through `@terminator/extension-ui`. Four of the dialogs gain the Escape key, a focus trap and a close control that they lacked. Every "N ago" in the core and the extensions comes from `RelativeTime`, so five minutes reads the same everywhere
- The application database is `userData/app.sqlite`, opened through Node's built-in `node:sqlite`, instead of PGlite (`app.pglite`). A start no longer loads about 250 MB of WebAssembly Postgres or spends about 0.6 s opening it. On the first start after the upgrade, the notes and tasks in `app.pglite` are copied across once. `app.pglite` stays in place as a backup. A failed import is logged, and the app starts with an empty database. Notepad search matches with `LIKE`, which ignores case for ASCII letters only. `node:sqlite` is a release candidate in Node 24 (ADR-099)

- Electron 30.4.0 → 42.4.1; `node-pty@1.0.0` → `node-pty@1.2.0-beta.13` (NAN → NAPI migration). NAPI is ABI-stable, so `electron-rebuild` and the `npm run rebuild` script are removed. This resolves ADR-021
- Fastify 4 → 5 and `@fastify/websocket` 8 → 11. Websocket handlers now receive the socket directly, not `connection.socket`
- Vitest 2 → 4, Vite 5 → 7, electron-vite 2 → 5, electron-builder 24 → 26, Playwright 1.45 → 1.61. `vitest.config.ts` moved from `environmentMatchGlobs` to `test.projects` (node/jsdom split), which supersedes the removed `vitest.workspace.ts`

### Security

- All high and critical `npm audit` findings are resolved, and `npm audit --audit-level=high` now passes: Electron, Fastify/`fast-uri`, `ws`, Vitest, esbuild/Vite, `node-ical`, `diff`, and the `electron-rebuild`→`cacache`/`node-gyp`/`tar` chain
- Removed the unused `@modelcontextprotocol/sdk` dependency from task-vault (dead since ADR-020). This clears 3 high advisories
- The remote-control bridge `send` and `subscribe` paths now pass through the allowlist, as `invoke` did before. This closes an event-eavesdropping and fire-and-forget gap on the server, which binds `0.0.0.0`
- ADR-017 is rewritten to make `0.0.0.0` the explicit decision, with a documented threat model and an accepted-risk statement. Before, it contradicted itself: the body said "MUST bind 127.0.0.1" and an amendment said the opposite

### Fixed

- A ticket opened on Home is drawn with its styles. Its header, tags, sections and buttons took their rules from sheets that only the sidebar's issue drawer and Settings load. Until one of those had opened, the ticket showed as unstyled text and browser buttons. The shared sections now load `issue-sections.css` themselves, and the buttons in the ticket view and the issue drawer are the design system's `Button`. Markdown lists, paragraphs and headings everywhere in the core window keep their spacing. The core reset now sits in `@layer reset`. Before, it tied the design system's `:where()` rules and, because it loaded after them, set their margins and padding to 0
- Controls side by side line up everywhere. Every control of a size has one height (`--tm-control-height` 28px, `--tm-control-height-sm` 22px): fields, selects, `Button` and `IconButton`. Before, padding set their size (31px and 23.6px), or they were a fixed 26px and 20px. Rows that mixed sizes (review header and footer, merge flow, Task Vault edit and blocked rows) use one size. The core's work-item field, session buttons, extension buttons and the diff's line expanders use the tokens. An e2e audit (`control-alignment`) checks every main screen
- Remote Control goes public while another ngrok runs. It gives its own agent an API port instead of reading 4040
- Task Vault: a row's actions show for keyboard focus, not only for the pointer
- Every text field, textarea and select is the design system's field (`controls.css`): themed background, border, padding and placeholder, and an accent edge with a soft ring on focus. Before, a field whose class lived in a sheet not yet loaded was the white OS widget. The terminal-name dialog showed one until Settings had opened once. Fields inside a box that draws its own edge (searches with an icon) keep their look. The sidebar search box now shows focus
- Extension toasts no longer sit under the extension's view. While an extension's view is on screen (or its frame, in the browser), the core leaves that extension's toasts to the view.
